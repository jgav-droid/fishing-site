## 3. Proposed factual access schema: what the sources actually support

Data is held **per access point**, because one lake can have several managers
with different rules. For example, at Lake Meridian the WDFW ramp needs a
pass, while the City of Kent dock's pass/fee status is unknown. Lake-level
values summarize the *primary shore-fishing access point*.

| Field | Supported? | Best source(s) | Notes |
|---|---|---|---|
| water_id, lake centre coordinates | **reliable** | WDFW lake page | 20/20 |
| bank_fishing_status (YES/LIMITED/NO/UNKNOWN) | **reliable** | WDFW lake page note + WDFW ShoreFishingSites GIS | Needs a human read once: the WDFW rating is "Good" on 583 of 598 pages, even where the note says "limited" |
| fishing_pier_or_dock | **mostly** (17/20) | WDFW GIS, WDFW access-site "Fishing platforms", manager pages | One conflict (Kapowsin) |
| public_access + access_manager | **reliable** | WDFW lake page names the managing park; WDFW access sites | 20/20 |
| parking_available | **reliable** (19/20) | WDFW access site "Parking lots"; manager feature lists | Green Lake: not stated |
| parking_or_access_fee | **partial** (15/20) | State Parks / county fee pages; WDFW pass rule | Municipal pages often silent |
| pass_required / pass_type | **partial** (12/20) | WDFW: "Discover Pass or Vehicle Access Pass is required at all WDFW recreation lands"; State Parks; county "not accepted" statements | Merged with fees, "pass or fee known": 15/20 |
| operating_hours | **partial** (10/20) | Park pages | WDFW access sites publish none |
| seasonal_access | **mostly** (15/20) | WDFW access-site "Access area open" dates; park pages | |
| angler eligibility / lake rules | **reliable** | WDFW lake page "Special fishing restrictions" + pamphlet | Juvenile-only waters: Long's Pond, Bradley |
| emergency_rule_source | **reliable** (20/20) | `emergency-rules?lake=<id>` + RSS | |
| current_notices (closures/construction) | **event-driven** | Manager page notice blocks; State Parks Alerts | 2/20 lakes have notices today |
| water_quality_advisory | **event-driven** | WA Ecology nwtoxicalgae.org table | Spanaway listed today |
| access_coordinates | **mostly** (17/20) | WDFW access-site lat/lon; WDFW shore points | |
| official_access_url, secondary_official_url | **reliable** | | |
| last_verified_at, confidence, provenance per value | built | | Every value carries source URL, quote and retrieval time |
| source_last_updated_at | **not reliable** | | Most manager CMS pages send no Last-Modified, or the fetch time instead. Use our own change-detection timestamp |
| accessibility_notes | **partial** | WDFW access-site ADA fields; county ADA pages | Not scored |
| review_required, update_type | built | | |

Fields **not** proposed, because no source supports them reliably:

- a lake "open/closed" flag;
- real-time parking availability;
- crowding;
- per-dock hours.

**Adding a new lake:**

- WDFW-access lake: about **5–10 minutes**. Templates do most of the work;
  a human assigns the shore state.
- State-park lake: about **15 minutes**.
- Lake run by a new local park department: about **15–30 minutes**. That
  covers finding the official page, reading hours, fees, dock and notices,
  and usually one fruitless search for a fee statement.

## 9. Ongoing maintenance

Assumptions per lake per year:

| Primary access family | Material changes reviewed | False alerts | Yearly re-verify |
|---|---|---|---|
| local park | 8 | 6 | 5 min |
| state park | 4 | 2 | 3 min |
| WDFW access | 2 | 3 | 2 min |

Every family also gets 3 emergency-rule items triaged per lake per year.
Each change review takes 6 min, each false alert 1.5 min, and each rule
item 2 min. Fixed ops (feeds, broken parsers, URL moves) are 2 h/month plus
0.5 min per lake per month.

| Lakes | Manual review h/month | Ops h/month | **Total h/week** | Range (0.5×–2× change rate) |
|---|---|---|---|---|
| 20 | 1.3 | 2.2 | **0.8** | 0.65–1.1 |
| 50 | 3.3 | 2.4 | **1.3** | 0.9–2.1 |
| 200 | 11.4 | 3.7 | **3.5** | 2.2–6.1 |
| 500 | 26.9 | 6.2 | **7.6** | 4.5–13.8 |

**Automated** (no founder time): stocking refresh, emergency-rule RSS and
lake filters, the algae table, State Parks Alerts, WDFW template re-ingest,
and change detection.

**Manual:** reading changed local pages, resolving ambiguous notices,
validating fee and hour changes, user-reported corrections.

**Seasonality:** load clusters around opening day (4th Saturday in April)
and the Memorial Day / Labor Day fee seasons. Peak weeks could run about 2×
the average.

**Calibration:** the change rates are assumptions. The 1-week Step 1 monitor
plus a 4–6 week run of `probes/change_detection.py` on these 27 pages would
calibrate them.

## 10. Temporary closures and rule monitoring

**What exists:**

- **WDFW emergency rules:** RSS feed, newsroom RSS, and a stable per-lake
  query (`?lake=<id>`). Lake IDs come from the page's own taxonomy; the names
  match WDFW lake-page titles.
- **WDFW access-area seasons:** a structured field on each access-site page.
- **WA State Parks:** a dated Alerts block on each park page. There is no
  feed; `parks.wa.gov` has no alerts index (404).
- **WA Ecology:** one statewide table of lakes above toxin guidelines.
- **Local parks:**
  - dated announcement blocks: SeaTac ("Posted 10/26/2026"), Pierce County
    ("Temporary Park Closure… Oct. 22, 2026"), Clark County project updates,
    Kent "Park Updates/Announcements";
  - a closure/alerts link (Snohomish County);
  - nothing structured: Seattle, Lacey, Lakewood, Puyallup, Tacoma Power
    (notes only).
- **No API or RSS was found for any local park department.**

**Feasibility:** yes, without rereading every lake. Feeds and per-lake
filters cover rules; one page covers algae; a hash on the normalized `<main>`
text flags local page changes for review, with 0/27 false changes observed.

**Gaps:**

- WDFW access sites have no notice field. A closed ramp would only show up
  if the page text changed.
- Physical closures announced only on signs or social media are invisible.
- The product must say "per <source>, as of <date>", never "open".

**Keep the facts separate:**

| Fact | Example |
|---|---|
| stocking event | Battle Ground, 1,080 rainbow on Oct 27 |
| fishing regulation | Clear Lake (Pierce) season ends Oct 31; Bradley juvenile-only |
| physical access status | Ward Lake's WDFW access area is listed as open only Apr 25 – Sep 30; Spanaway Park closed to vehicles Oct 24 – Jan 11 |

## 11. Example trip-decision outputs (`trip_decisions.txt`)

Six records are generated for 2026-10-31: Battle Ground, Klineline,
Spanaway, Bradley, Ward and Clear (Pierce). Each combines **6–8 official
pages from 2–3 agencies** into one record. The WDFW stocking report alone
answers only "was it stocked".

**In 5 of 6, a trip-changing fact is absent from any stocking table:**

- **Spanaway:**
  - park closed to vehicles until Jan 11; walkers 7–11 a.m. only;
  - pier closed until 2027;
  - toxic algae above guidelines (Ecology, Oct 27).
- **Ward:** WDFW access area outside its listed season (Apr 25 – Sep 30),
  even though the lake was stocked Oct 26.
- **Clear (Pierce):** fishing season and vehicle access end Oct 31.
- **Bradley:** juveniles, seniors and disabled anglers only.
- **Klineline:** $5 county parking fee; Discover Pass not accepted.

Alternatives listed in each record carry their own restrictions, for
example "Long's Pond … RESTRICTED: juvenile/senior/disabled anglers only".
Fry plants are excluded from "recently stocked": October's "56,112 kokanee"
at American Lake were fry at 40.5 fish/lb.

## 14. Remaining risks

- **Municipal pass/fee and hours gaps** (5 and 10 lakes). Options: accept
  "not stated by <manager>" in the UI; a one-time email to 5 park
  departments; or prefer WDFW and State Parks lakes in the MVP.
- **Change rates are assumed, not measured.** Run change detection for 4–6
  weeks before trusting the maintenance hours. Peak season may double them.
- **Local closures posted only on signs or social media** are invisible to
  any official-web monitor.
- **Conflicts need human judgement:** Kapowsin dock; Meridian ramp manager
  and fee; Martha pier count; Long's Pond wording and the city license claim.
- **WDFW data defects** (codes L2818 and L3218/L3219) also affect WDFW's own
  lake-page plant tables.
- **The WDFW shoreline rating is uninformative** ("Good" on 97% of rated
  pages), so YES vs LIMITED needs one human read per lake.
- **Scaling beyond about 200 lakes** pushes maintenance past 3 h/week. Past
  50 lakes, prefer lakes with WDFW access and State Parks.
- **URL drift** (Puyallup domain and page-ID change). Monitors must treat
  404s and redirects as review items.
- **Labels and states were assigned by the validating agent.** A human
  should spot-check `access_dataset.json` for the MVP before launch.

## 15. Recommendation: proceed to Step 4, with two access-layer fixes alongside

The access layer is feasible and cheap to maintain at MVP scale: about 1.3
founder-hours/week for 50 lakes, with most data static or periodic and
events monitorable through feeds and change detection. The combined record
materially changes trip decisions.

Do these alongside Step 4. Neither blocks it.

1. **Pass/fee at municipal parks:** pick a display rule for UNKNOWN ("not
   stated by <manager>") and try a one-time confirmation with the 5 park
   departments.
2. **Calibrate maintenance:** schedule `probes/change_detection.py` weekly
   for 4–6 weeks, alongside the Step 1 monitor, and replace the assumed
   change rates.

Do not expand past about 50 lakes until those numbers are in. When
expanding, prefer WDFW-access and State Parks lakes; local-park lakes cost
about 1.7× in setup (18.5 vs 11 min) and about
2.8× in maintenance (68 vs 24.5 min per lake-year).
